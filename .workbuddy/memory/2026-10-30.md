## 补记（21:22）：日志底座换 Log4j2

用户说「换 Log4j2 试试」。动机成立：Log4j2 有**原生 FATAL**（logback 没有，之前 CRTL 只能靠 Marker 模拟），
后面还能上 AsyncLogger（Disruptor），WS 帧密集时有用。

改动：
- `libs.versions.toml`：logback 2.26.1 → log4j 2.26.1（api / core / slf4j2-impl）；`logback.xml` 删，新增 `log4j2.xml`。
- `ShortLevelConverter` 重写成 Log4j2 插件（`@ConverterKeys` + `LogEventPatternConverter`）。
- **`ShortLoggerConverter` 直接删了**：Log4j2 内置 `%logger{2}` 就是「上一级包+类名」，不用自己写。
- CRTL 现在两条来源：原生 `log.fatal(...)` 与 `log.error(Critical.CRITICAL, ...)`；demo 里两条都打了。

踩的坑（比 logback 那次更隐蔽）：
1. **键名 `%lvl4` 不能要**：Log4j2 把 `%l` 当内置「行号」缩写先匹配，渲染出 `vl4`。改成 `%LVL4`。
   这个坑很阴——不跑一次根本看不出来，单测里断言 pattern 输出才抓住。
2. `annotationProcessor(log4j-core)` **不继承 implementation 的 BOM**，版本解析成空 → 必须
   `annotationProcessor(platform(log4j-bom))`。
3. log4j-core 的注解处理器会报 GraalVM 参数缺失警告 → 补 `-Alog4j.graalvm.groupId/artifactId`。
4. 测试里 `PatternLayout.doLayout` 不存在，要用 `toSerializable`；`withPattern` 已过时 → `setPattern`。

结果：25 个用例全绿，`--demo-log` 输出与 logback 版**形状完全一致**，且多了原生 FATAL 那条 CRTL。

用户定「用 Boot4」。Boot 3 不支持 Java 25（class file 69），所以只能 4；取 **4.1.2 + WebFlux**。

- 依赖走 Boot BOM；`spring-boot-starter-webflux` + `spring-boot-starter-log4j2`。

  `TextNode` 改名 `StringNode`；`asText()` → `asString()`；Jackson 3 的异常全是非受检（`JacksonException extends RuntimeException`），
  所以「读文件 IO」和「JSON 解析」拆成两段 catch。Jackson 3 的 API 全部用 javap 离线核对过。
- 新增 `admin/AdminConfigController`：`GET /api/admin/config`（返回 `JsonNode`）+ `/config/meta`。

- `.run` 里 gradle 任务 `run` → `bootRun`。

四个坑：
1. **`spring-boot-starter-logging` 必须全局 exclude**：Boot 4 把它挂在 `spring-boot-starter` 下，
   对 webflux 那条边 exclude 等于没写，否则 Logback 与 Log4j2 双绑定并存。
2. **`SERVER__PORT=8942`**（宿主注入的环境变量）被松弛绑定认成 `server.port`，优先级高于默认属性 →
   测试里一直撞 8942 端口占用。改成命令行参数才压得住。
3. `@SpringBootApplication` 的类不能有「私有构造 + AssertionError」——Spring 要实例化它，
   第一次启动直接 `AssertionError: no instances`。
4. 入口在 `app` 子包，兄弟包 `admin` 扫不到 → `scanBasePackages`。第一次冒烟是 404。
